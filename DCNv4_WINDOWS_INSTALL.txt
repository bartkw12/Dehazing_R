DCNv4 install notes for Windows

What is actually failing
- This project does not just import CUDA-enabled PyTorch. It builds a custom CUDA extension from source under `DCNv4_op`.
- On Windows, that build needs all three of these pieces working together:
  1. PyTorch CUDA runtime
  2. NVIDIA CUDA Toolkit with `nvcc`
  3. Microsoft C++ compiler `cl.exe` plus the MSVC build environment
- If `nvcc` exists but `cl.exe` is missing, the build will still fail.

Important distinction
- The Developer PowerShell for VS 2022 does not install anything by itself.
- It gives you a shell with the Visual Studio C++ build environment loaded.
- If the Build Tools are already installed, using that shell is often enough to make `cl.exe`, `INCLUDE`, and `LIB` available.
- If the required Build Tools components are missing, you must install them through Visual Studio Installer first.

What you need installed
1. Miniconda or Conda env with Python 3.8 and your PyTorch stack.
2. NVIDIA CUDA Toolkit 11.3 available on disk.
3. Visual Studio Build Tools with C++ support.

Recommended Visual Studio Installer components
1. Desktop development with C++
2. MSVC v143 - VS 2022 C++ x64/x86 build tools
3. Windows 10 SDK or Windows 11 SDK
4. Optional but recommended for CUDA 11.3: MSVC v142 - VS 2019 C++ x64/x86 build tools

Local compatibility notes in this repo
- `DCNv4_op/setup.py` includes `-allow-unsupported-compiler` for newer Visual Studio toolchains.
- The local CUDA sources compile without `BFloat16` dispatch to avoid CUDA 11.3 BF16 build failures on Windows.

How to open the correct shell
1. Close all existing VS Code windows and terminals.
2. Open the Windows Start menu.
3. Search for one of these:
   - `Developer PowerShell for VS 2022`
   - `x64 Native Tools Command Prompt for VS 2022`
4. Open one of them.
5. In that shell, run these checks before doing anything else:
   - `where.exe cl`
   - `cl`

Prefer the x64 shell
- If you have both x86 and x64 developer shells available, prefer the x64 one.
- For a 64-bit Python environment, you want `cl.exe` from an x64 toolchain when possible.

What you should see
- `where.exe cl` should print a path to `cl.exe`.
- `cl` should print Microsoft C/C++ compiler version information.
- If both fail, the C++ toolchain is not available in that shell.

If `cl.exe` is still missing
1. Open Visual Studio Installer.
2. Find your Build Tools installation.
3. Click Modify.
4. Make sure the components listed above are installed.
5. Reopen the Developer PowerShell after the install finishes.

Conda note
- If Conda warns that `PATH` is configured as an env var for the environment, remove it once with:
  `conda env config vars unset -n dehazedct PATH`

How to prepare the shell for this project
1. Open Developer PowerShell for VS 2022.
2. Activate the Conda environment:
   `conda activate dehazedct`
3. Set the CUDA toolkit location for the current shell:
   `$env:CUDA_PATH = "I:\Install\NVIDIA TOOL KIT OTHER"`
   `$env:CUDA_HOME = $env:CUDA_PATH`
   `$env:PATH = "$env:CUDA_PATH\bin;$env:CUDA_PATH\libnvvp;$env:PATH"`
4. If you are already inside a Visual Studio developer shell, tell Python build tools to use that active VC environment:
   `$env:DISTUTILS_USE_SDK = "1"`

Sanity checks to run in that shell
1. `python -c "import torch; print(torch.cuda.is_available()); print(torch.version.cuda)"`
2. `python -c "from torch.utils.cpp_extension import CUDA_HOME; print(CUDA_HOME)"`
3. `where.exe nvcc`
4. `nvcc --version`
5. `where.exe cl`
6. `cl`

Expected results
1. PyTorch should report `True` for CUDA availability.
2. `torch.version.cuda` should print `11.3`.
3. `CUDA_HOME` should print your toolkit path.
4. `nvcc` should be found and show CUDA 11.3.
5. `cl.exe` should be found and print compiler information.
6. `DISTUTILS_USE_SDK` should be set to `1` before building if the shell already has the VC environment loaded.

How to use that shell with VS Code
1. Stay in the Developer PowerShell after the checks pass.
2. Change into the project folder.
3. Run `code .`
4. VS Code will open inheriting the environment from that shell.
5. Open a new integrated terminal in that VS Code window only after launching VS Code this way.

Why this helps
- Starting VS Code from the Developer PowerShell passes the working MSVC environment into the integrated terminal.
- That is usually more reliable than manually editing the system `PATH` and reopening random shells.

Install order for this repo
1. Install pure Python dependencies:
   `pip install -r requirements-inference.txt`
2. Clean any previous DCNv4 build output:
   `pip uninstall -y DCNv4`
   `Remove-Item -Recurse -Force .\DCNv4_op\build -ErrorAction SilentlyContinue`
   `Remove-Item -Recurse -Force .\DCNv4_op\dist -ErrorAction SilentlyContinue`
   `Get-ChildItem .\DCNv4_op -Filter *.egg-info | Remove-Item -Recurse -Force -ErrorAction SilentlyContinue`
3. Install build helpers:
   `pip install --upgrade pip setuptools wheel ninja`
4. Build the local extension from the Dehazing_R root:
   `pip install --no-build-isolation -e .\DCNv4_op -v 2>&1 | Tee-Object -FilePath .\dcnv4_build.log`

If the build log says the VC environment is activated but `DISTUTILS_USE_SDK` is not set
1. Stay in the same developer shell.
2. Run:
   `$env:DISTUTILS_USE_SDK = "1"`
3. Clean the DCNv4 build output again.
4. Retry the install command.

Why `--no-build-isolation` helps
- It makes pip build the extension against the packages already installed in your active Conda environment instead of a temporary isolated build environment.

Commands you should not use for this repo
- `pip install DCNv4`

Command you should use from the Dehazing_R root
- `pip install --no-build-isolation -e .\DCNv4_op`

Short diagnosis guide
- `nvcc` works, `cl.exe` missing: open Developer PowerShell or fix Build Tools installation.
- `nvcc` works, `cl.exe` found, but the build says VC environment is activated and `DISTUTILS_USE_SDK` is not set: set `$env:DISTUTILS_USE_SDK = "1"` and retry from the same developer shell.
- `cl.exe` works, `nvcc` missing: fix `CUDA_PATH`, `CUDA_HOME`, or CUDA Toolkit installation.
- Both work in Developer PowerShell but not in VS Code: launch VS Code from the Developer PowerShell using `code .`.
